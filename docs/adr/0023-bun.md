# 0023. Bun installs and runs the scripts

Status: Accepted, 2026-11-15 (TOB-491). Supersedes the npm decision of [0012](0012-npm-node-and-the-desktop-runner.md).

## Context

[ADR 0012](0012-npm-node-and-the-desktop-runner.md) kept npm over Bun, the package manager in Toby's project standard (TGstack `new-project`), because the app had no runtime dependencies and a switch would buy little. Since then [ADR 0021](0021-react-typescript-effect.md) added React, Effect, Vite and TypeScript, and Toby has chosen to follow the standard.

## Decision

- Bun is the package manager. `bun.lock` replaces `package-lock.json`. It was migrated from the npm lock and resolves the same 129 packages at the same versions and integrity hashes.
- Every command runs through Bun: `bun install --frozen-lockfile`, `bun run <script>` and `bunx playwright`. `pretest`, `prebuild` and `dev` call `bun run`, and Bun runs `pre*` scripts as npm does.
- CI installs Bun 1.4.2 with `oven-sh/setup-bun@v2` next to Node 24. The deploy tells `cloudflare/wrangler-action` to use Bun (`packageManager: bun`).
- Node stays the runtime. `server.mjs`, `scripts/build-static.mjs`, the unit tests (`node --import tsx --test`) and Playwright's web server still run on `node`, and Bun starts Node for every `#!/usr/bin/env node` binary.

The Node, no-bundler, hosting and lint decisions in 0012, and the runner decision in [0018](0018-ci-on-hosted-runners.md), stand.

## Consequences

- `bun run test` runs the build and the unit tests. `bun test` is Bun's own test runner, finds none of them and skips the build.
- Bun ignores the `libc` field, so on Linux it also installs the unused musl builds of the oxlint, rolldown and lightningcss bindings, about 45 MB. Each package loads the binding that matches the system.
- `bun.lock` holds no root version, so a release bumps `package.json` and the footer only.
- Moving a script from Node to the Bun runtime needs evidence that its output is unchanged: a byte-identical `dist/`, or the same tests with the same results.
