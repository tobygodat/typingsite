# Typing feedback latency — 22 September 2026

## Method

The reference machine was a Linux desktop with an Intel Core Ultra 7 155H. The browser was Chromium 152. Both builds were checked in the Codex in-app Chromium browser at a 1280 × 720 CSS-pixel viewport. A temporary browser probe counted individual `keydown` events sent to the focused typing field and observed Event Timing `keydown` durations. These durations run from the event timestamp to the next paint. Chromium reports them in 8 ms steps. The probe recorded every keydown and no window blur or hidden-tab event in either 900-key run.

`scripts/measure-latency.mjs` is the repeatable standalone measurement. It starts the local app and a fresh Chromium profile, types through CDP `Input.dispatchKeyEvent`, checks the exact target prefix, verifies the current character remains in the three-line viewport, and reports Event Timing plus DOM-mutation and animation-frame proxies. Run it when the desktop browser has exclusive focus:

```sh
DURATION=120 KEYS=900 KEY_DELAY_MS=30 node scripts/measure-latency.mjs
```

The script rejects a hidden tab or any focus loss. A simultaneous browser task can steal focus and invalidate paint timing. The in-app run avoided that conflict; its probe was removed from application code after verification. The measurement starts at the browser event. It excludes the physical keyboard, operating-system input queue, display scanout and photons.

## Results

| Build | Viewport | 900 individual keys | Event-to-next-paint p95 | Mounted passage characters after 900 keys |
| --- | --- | ---: | ---: | ---: |
| Afterimage on `master` | 1280 × 720 | 900 observed, no blur | 64 ms | 8,465 |
| Bounded passage renderer | 1280 × 720 | 900 observed, no blur | **32 ms** | 738 |

Both runs used the same browser, machine, viewport, 120-second passage setting and individual key input. Passages were randomly generated, so the measurements are a matched-browser comparison, not a controlled experiment with identical content. The final run's longest reported event was 48 ms. Its 630 px spacer held the trimmed passage's height, and the current character and caret remained aligned in the visible three-line area. After 800 backspaces, the older text remounted and the caret stayed aligned at character 100. An intentionally wrong letter retained the wavy underline and corrected normally in a separate Chromium run.

The renderer now mounts an initial word range, adds words ahead of the cursor, and removes complete lines behind it. Scoring and deterministic replay still retain the full target. The proposed under-50-ms p95 browser event-to-paint budget was observed in the final in-app run. Broader devices, browsers, input methods and physical key-to-display latency remain unmeasured.
