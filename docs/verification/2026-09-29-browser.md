# Browser verification — 29 September 2026

This is the first browser verification of the Afterimage build. The checks in `docs/verification/2026-09-22-browser.md`, which ran on the build before the redesign, are now a Playwright suite in `e2e/`. It also covers the redesign's own behaviour (theme, command palette, ghost pacer, the still-run fade, reduced motion) and accounts. Run it with `npm run test:e2e` (see README).

Environment: Linux desktop, Node 26, Playwright 1.63 driving system Chromium 152 in headless mode. Desktop is 1280×800; phones are 390×844 and 320×640 with touch and mobile emulation. The app is served on `127.0.0.1:4173`, and Supabase is replaced by an in-memory fake (`e2e/fake-supabase.js`), so no account or network is touched. Each test fails on any page error, console error or fake-handler error.

Result: 41 of 41 tests passed. Repeated runs under parallel load (`--repeat-each` 2–6, up to 11 workers) also passed, except for one intermittent hang recorded under Limits. The numbers are automation results, not human performance or learning evidence.

## Limits and findings

- **Known defect:** below about 354 px, some three-digit wpm scores overflow the run card. The 112 px numeral plus "wpm" needs 276 px of content width, so a 322 px card appears on a 320 px screen. The phone tests type at about 60 wpm, where the card fits. Fixing it needs a smaller numeral token for narrow screens.
- The member sign-out/sign-in test hung at its second sign-in: once in a full `--repeat-each 3` run, then six times out of six in an accounts-only `--repeat-each 6` run. In the failure inspected, the Sign in button stayed disabled and the trace shows no second token request. It did not recur in later stress runs (54 of 54 for the accounts file, then full runs at `--repeat-each 3` and `2`). Its cause is unknown, so treat a recurrence as a real signal.
- This is one browser engine with synthetic key events. Touch keyboards, IME composition, assistive technology, other browsers and physical key-to-display latency still need device testing. Window blur ("Focus lost") is not exercised because headless pages do not lose focus.
- The fake Supabase follows the endpoints `src/account.js` calls. It is not the real service, so Google provider setup and redirect URLs still need one manual check against the live project.
