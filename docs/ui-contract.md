# UI contract

This document is the integration contract between the static interface in `index.html` and the behavior in `src/app.js` (with `src/motion.js`, `src/graph.js`, `src/palette.js` and `src/egg.js`). The app is a single document with one shared typing surface so practice, targeted drill, and fresh-text retest preserve the same geometry and input behavior.

## Screen model

- `body[data-view]` is one of `practice`, `results`, `progress`, `compete`, or `learn`. `learn` has no dock item; it opens from `[data-action="open-lessons"]` (the quiet "learn to type" link in the practice controls and the first-run links) and the palette.
- Only the matching `[data-screen]` is visible. Navigation controls use `[data-nav]` with the same values and set `aria-current="page"` (and `.is-active`) on the active item. The dock labels them practice, train, progress and challenge; the brand link also navigates to practice.
- `#typing-screen` is the shared typing surface. Its `data-session` value is one of `practice`, `drill`, `retest`, `daily`, or `lesson`; `body[data-session]` mirrors it for styling.
- Results, progress, and challenge use `#results-screen`, `#progress-screen`, and `#compete-screen`.
- `body[data-running]` is present from the first keystroke of a run until it finishes or restarts. While it is set, chrome other than the passage and its measure row fades out; pointer movement, finishing or restarting brings it back. It never changes the passage geometry.
- Buttons with `[data-action]` expose intent for delegated event handlers. All navigation and state changes happen without a page reload.

## Theme

`html[data-theme]` is `dark` or `light`. An inline script in `<head>` resolves it before first paint from `preferences.theme` in the `stilltype-profile-v2` profile, falling back to `prefers-color-scheme`. The stored preference is `system`, `dark` or `light`; `system` follows the OS and updates when it changes. `meta[name="theme-color"]` is kept in step with the resolved theme.

## Dock, settings and command palette

The dock (`nav.dock` in `.dock-zone`) holds the brand link, the `.dock-nav` view buttons, the settings popover (`details.preferences`, whose `summary.dock-settings` shows an icon and the label "settings") and `#palette-trigger`. The popover is positioned against the dock: below it on desktop, above it on mobile. Restart (`#restart-button`) stays in the typing footer.

The collapsed `#test-content-settings` category contains `#word-list` and `#numbers-toggle`. Numbers default off, apply only to time/word tests, and remain available through the "numbers" command. They are recorded in run conditions, keeping bests and retests separate from runs without numbers. Quote and daily passages ignore the preference. The passage mode bar has no numbers control.

Selection pills: a `.glide` container with `data-glide="current"` follows `aria-current`; `data-glide="pressed"` follows `aria-pressed`. Its `.glide-pill` is aria-hidden decoration; state always lives in the ARIA attributes and `.is-active`.

Settings are `#theme-select` (`system`, `dark`, `light`), `#font-size` (`22`, `28`, `36`), `#speed-unit` (`wpm`, `cpm`), `#live-toggle`, `#keyboard-toggle`, `#stop-on-error-toggle`, and `#focus-toggle`; `#exit-focus` sits outside the dock. Apply theme as `html[data-theme]`; font size as `body[data-font-size]`; live metrics as `body[data-live-metrics]`; keyboard as `body[data-keyboard]`; focus mode as `body[data-focus-mode]`. Stop on error defaults on; turning it off permits advancement after mistakes. Changing the correction policy starts a new practice run. The policy is stored in run conditions, keeping bests and comparisons separate. The speed unit is display only: every speed is saved, scored, compared and keyed in wpm, and shown in the chosen unit (cpm = wpm × 5, `src/units.js`). Static unit labels carry `data-speed-unit` (empty for the bare unit, otherwise `%` marks where the unit goes) and the run card's definition (`#speed-definition`) and raw speed tooltip (`#result-raw-row`) are worded for the chosen unit; changing the unit redraws the figures already on screen (toasts included) without starting a new run, closing open Progress rows or moving focus. The generated keyboard belongs in `#keyboard`. Escape or `#exit-focus` exits focus mode before applying the ordinary Escape restart behavior.

The command palette is `dialog#palette`. `#palette-input` is a combobox controlling `#palette-list` (a listbox rebuilt from the app's commands on every keystroke, so hints show current state); `#palette-empty` shows when nothing matches; `.palette-highlight` is aria-hidden. Ctrl-K / ⌘K and `#palette-trigger` open it; Escape closes it and returns focus. Opening it closes settings, and opening it during a run marks that run interrupted.

## Shared typing surface

Required IDs: `typing-screen`, `typing-form`, `typing-input`, `typing-wrap`, `text-display`, `accessible-passage`, `live-stats`, `live-wpm`, `live-accuracy`, `timer`, `timer-unit`, `timer-label`, `progress-track`, `progress-bar`, `typing-status`, `session-kicker`, `session-title`, `session-description`, `condition-line`, `input-help`, `restart-button`, and `announcement`.

`#text-display` receives `.word > .char` spans. Character state classes are `.correct`, `.wrong`, and `.current`; they change instantly, without transition. `.wrong` always has a non-colour tint; on a space it is painted at full line height so the row keeps an even band. Under `forced-colors: active` it switches to the system `Mark` / `MarkText` highlight so the mark survives the forced palette. The display has a fixed three-line height; live metric updates must not change its geometry. `src/motion.js` inserts only two aria-hidden elements into the display after each render, `.caret` and `.ghost-caret`, drives the ~150 ms line scroll, and sets `data-caret` / `data-blocked` on `#typing-wrap`.

`#typing-input` is the real focus target and remains visually transparent over the displayed text. `#progress-track` is a thin line with `role="progressbar"`; keep `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, and `aria-valuetext` current. `#progress-bar` fills from its `--progress` custom property (0–1), not its width.

`#live-stats` is plain text and is not a live region; update it at a restrained cadence. Completion is announced once through `#announcement`.

Practice mode controls are `#mode-time`, `#mode-words`, `#mode-quote`, `#mode-standard`, `#duration-options`, `#punctuation-toggle`, `#quote-options`, `#quote-length`, and `#quote-difficulty`. Generated length buttons belong in `#duration-options` and use `aria-pressed`. `#mode-compose` sits in the same group (`data-compose`, not `data-mode`) and opens composing practice.

`#mode-standard` selects the standard test: one fixed, versioned recipe (`STANDARD_VERSION` in `src/typing.js`, now `standard-v1`) of 60 s, stop on error, sentences from the 1k/5k/10k word bands with punctuation and numbers, the second of them in quotation marks as the quote segment. Every word, the quote's included, comes from the attempt's own seed (`standardPassage`), recorded in the text ID, so no attempt repeats text from the quote corpus or an earlier attempt. On layouts where `"` is a dead key, browsers report composition, which isn't scored, so those typists need #61 (dead-key input) to complete a standard run. Its conditions carry `recipe`, which `conditionKey` appends only when present, so it has its own bests, trends and retests. While it is selected, `#standard-options` (with `#standard-recipe`) replaces the length buttons, and `#punctuation-toggle`, `#word-list`, `#numbers-toggle` and `#stop-on-error-toggle` are disabled with the recipe's values (numbers on) and, in settings, a `.preference-lock` note; the palette leaves out the punctuation, numbers and word list commands. Standard conditions carry no `numbers` field, since the recipe fixes them, so standard keys are unchanged by the numbers toggle. `#word-list` gains its recipe option (`standard`) only while standard is selected, and `setWordList` accepts only real list IDs; the person's own settings are kept for the other modes.

## Composing practice

`body[data-compose="true"]` while composing is open: `#typing-form` is hidden and `#compose-form` (`data-state` `ready` or `done`) takes its place on the practice screen; the length options and `#punctuation-switch` are hidden and the footer best is hidden. The form holds `#compose-prompt`, `#compose-conditions`, `#compose-another`, `#compose-timer`, the free-typing `#compose-input` (described by the prompt, `#compose-hint` and `#compose-privacy`), the `#compose-progress` progressbar, `#compose-help` for notices, `#compose-restart` and `#compose-done` (Ctrl/⌘+Enter). The result is `#compose-result`: `#compose-result-heading`, `#compose-wpm`, `#compose-backspace`, `#compose-active`, `#compose-characters`, the definition `#compose-definition`, `#compose-saved`, `#compose-retry` and `#compose-next`, which takes focus on finishing. Escape in the field starts over. Where `CSS.supports('caret-animation', 'manual')` is false, `src/compose-caret.js` sets `data-caret="drawn"` on `.compose-wrap`, which makes the field’s native caret transparent, and inserts one aria-hidden `.compose-caret-layer` after the field, holding an empty hidden mirror and the `.compose-caret` bar (no animation or transition, `hidden` unless the field is focused, writable and has a collapsed selection); otherwise it adds nothing. Choosing time, words or quote, a drill, a retest or the daily ends composing; settings and sync wait until it ends. Progress lists saved sessions in `#compose-history` (`#compose-history-note`, `#compose-history-list`), apart from the copy-test charts. Only numbers are stored, never the text.

`#best` in the footer shows the personal best for the current conditions, or states that there is none. `#suggest-trigger` beside it (and the palette command "suggest a feature…") opens `dialog#suggest-dialog`: `#suggest-text` (max 1000 characters, counted in `#suggest-count`), errors in `#suggest-error`, a hidden honeypot `#suggest-website`, and `#send-suggest`, which inserts `{ body, view }` into the Supabase `feature_suggestions` table through `sendSuggestion` in `src/account.js`, always as the anonymous role (a filled honeypot sends nothing). Success closes the dialog and shows `#suggest-toast`; failure keeps the text. Opening it mid-run marks the run interrupted, like the palette.

## Completed run and recommendation

`#results-heading` contains `#result-delta`, the one-line headline for the run. `#result-comparison-note` stays empty except for interrupted-run and storage messages.

The run card is `#run-card`: `#run-card-stamp` (date, time and session kind), `#speed-graph` (an SVG speed-over-time graph drawn by `src/graph.js` from the attempt's keystrokes, mistakes in coral; `role="img"` with a text summary in its `aria-label`; presentational only) and its legend, `#result-wpm`, `#result-accuracy`, `#result-errors`, `#result-time`, a one-line metric definition, `#result-conditions` and, after a run that counts as evidence and has missed or timed words (a complete test, retest or daily run, by the same rule as recurring patterns; never a drill, a daily passage shown before, custom text or word practice itself), `#practice-words-evidence` (the words missed on the first try, and this run's slowest clean words with their wpm beside the run's median and sample count) above `#practice-words`, which starts an uncounted `missed` practice run of those words. That run becomes the baseline for the fresh retest offered afterward, which reads and records no drill target. The card is a static print: numbers are set directly, with no tilt, reels or count-up.

Recommendation IDs are `recommendation-title`, `recommendation-evidence`, `recommendation-list`, `recommendation-meta`, `start-drill`, `skip-to-retest`, and `run-again`.

`#recommendation-evidence` must name observed evidence (error count and/or timing against the user's own median). When evidence is insufficient, say so directly and offer a general drill. `#recommendation-meta` states approximate drill time and that the retest uses a fresh comparable passage. Never render a confident weak-pattern claim without recorded observations.

Below the recurring patterns, `section.missed-words` lists the words you keep missing: `#missed-words-note` names what was counted (the newest counted runs that recorded missed words, up to 120 and up to 12 words each: complete tests, retests and new daily passages, the runs pattern memory reads, so never word practice, custom text, drills, interrupted runs or a daily passage shown before; only those on the newest such run's input class, since touch is never pooled with a physical keyboard), or says plainly that there isn't enough evidence yet and how much there is. With two or more words missed on the first try in at least two of those runs, `ol#missed-words-list` shows up to 8 (`li.missed-word`: the word, then "missed in N of the last M runs") and `#practice-missed-list` (accessible name "Practice these N words you keep missing", apart from the run card's button; also the palette command "practice words you keep missing") starts the same uncounted `missed` run with those words. Pressed over a list the runs no longer match (changed by a sync or another tab), it redraws the list first and practises the words the runs hold now; with fewer than two left it starts nothing, announces that and moves focus to `#missed-words-heading`. Clearing history empties the list, and Run again after it starts a normal test.

The manual target lives in `details.manual-panel` (summary `#manual-heading`): `#manual-target` form, `#manual-target-input`, and `#apply-manual-target`. It accepts a short letter pair or word. Validation appears in `#manual-target-error`; invalid state uses `aria-invalid="true"` and visible recovery copy.

## Drill and retest

`#start-drill` changes the shared typing surface to `data-session="drill"`; the page uses the same input and text display with target-heavy generated text. `#skip-to-retest` and drill completion change it to `data-session="retest"`; the passage must be fresh and the condition line must say whether comparison is valid.

Retest outcome IDs are `#comparison-panel`, `#comparison-status`, `#comparison-accuracy`, `#comparison-timing`, `#comparison-wpm`, `#comparison-sample`, and `#comparison-caveat`. The panel supports `data-outcome="improved|mixed|regressed|steady|insufficient|unavailable"`. The green accent appears only for `improved`; `mixed` uses warning. Regression uses plain coral (danger) ink and explanatory copy. Insufficient samples and incomparable conditions state that no claim can be made.

## Online challenge

Challenge defaults to `#online-challenge`; `#challenge-online`, `#challenge-daily`, `#challenge-friends` and `#challenge-local` select online, daily, the friends board or shared-keyboard play with `aria-pressed`. `src/online-race.js` owns online state and uses the same text renderer and caret effects as practice.

Hosts use `#online-name`, optional `#online-invite-email` and `#create-online-race`. Guests are offered `#online-signin` to host. Account invitations appear in `#online-invites` with `[data-accept-invite]` buttons. A fragment invitation opens `#online-guest-join` with `#online-guest-name` and `#join-online-race`.

`#online-room` contains `#online-room-status`, `#online-connection`, `#online-players`, `#online-ready` and `#online-leave`. A guest room exposes the copyable `#online-guest-link` and `#copy-race-link`; account rooms instead show generic delivery copy in `#online-account-invite-status`. Each player has a labelled progressbar with no decorative animation.

`#online-friends` (signed in only) lists `#online-friend-list` rows with `[data-race-friend]` (Challenge) and `[data-remove-friend]`; `#online-save-friend` beside `#create-online-race` appears once an email is typed. After a closed race with two players, `#online-after` shows `#online-rematch` (Race again, or Join rematch when the opponent asked first, explained in `#online-rematch-note`) and `#online-befriend` when the opponent is an account not yet on the list. The friend list's requests (reading it, the save when a race is created, Remove, and Add to friends) go one at a time, each sent once the one before has settled, and each reply is the whole list, drawn as it lands; a failed one holds nothing up. One that hasn't answered in 15 seconds has failed, and its fetch is aborted. A change (save, Remove, Add to friends) that failed or gave up may still have been made, so the list is read again before anything else goes, and the list shown is what the service holds. Once a read succeeds, `#online-friends-empty` shows its usual copy again, not an earlier failure.

The online race sends one race request at a time. While one is in flight, `#create-online-race`, `#join-online-race`, `#online-ready`, `#online-leave`, `#online-again`, `#online-rematch`, `[data-race-friend]` and `[data-accept-invite]`, and the inbox's and the toast's Join and Race again, are aria-disabled and ignore presses until it lands. Friend changes are separate: while Remove or Add to friends waits its turn or is out, `[data-remove-friend]` and `#online-befriend` are aria-disabled, and no race control waits for it. An aria-disabled button is dimmed as disabled and doesn't react to hover or press, but keeps keyboard focus with a full-strength ring (its colours dim instead of the whole box). Redrawing the friend list, the invitations or the inbox keeps focus on the same control; when a removed friend's row goes, focus moves to `#online-name`.

`#online-stage` contains `#online-countdown`, `#online-timer`, `#online-text-display`, `#online-accessible-passage` and `#online-input`. Input remains disabled until the shared start and after completion; paste, key repeat and composition are refused. `#online-results`, `#online-winner` and `#online-result-rows` display server results, with `#online-again` to return to setup. Leaving ends an active room; transient network failures retry without freeing the seat.

Room credentials and pending guest invites use expiring tab-scoped sessionStorage; guest run history remains unsaved. Online scores do not enter solo progress or bests. See [online race behavior and verification](online-races.md).

## Daily challenge

`#daily-challenge` contains `#daily-date`, `#start-daily`, `#daily-status` and `#daily-history-panel`. Daily uses the primary typing surface with `data-session="daily"`, fixed quote conditions and continue-on-error. Its UTC date is captured at start. Saved completed scores distinguish first/repeat attempts and fresh/previously displayed text. Daily scores stay out of practice trends and bests. Daily, Friends and One keyboard selectors are disabled while an online room is active.

## Friends board

`#friends-board` (`src/friends-board.js`) shows guests `#friends-board-guest` with `#friends-board-signin`. Signed in, `#friends-board-share` holds the opt-in switch `#share-board` (off by default; also the palette command "share on friends board") and, while it is off, `#friends-board-off`, the one line saying friends' rows are hidden too; nobody sees your row and no rows show until it is on. The switch shows the sharing state the service last reported to this device (the account's membership there is the only record; it is not a synced preference); before this device has read it, the switch is off, `#friends-board-off` stays hidden and the palette command has no on/off hint. A share the service refuses because sharing was turned off elsewhere after this browser last read it (its tabs share what each read) leaves the switch off, with `#friends-board-status` saying "Sharing was turned off on another device."; turning it on again from there shares. Sharing, `#friends-board-lists` holds `#board-daily` (today's best completed physical-keyboard daily attempt, with the attempt count), `#board-week` (completed, uninterrupted practice time since Monday 00:00 UTC, with the run count) and `#board-bests` (each person's best on the shape picked in `#board-shape`, the labelled "Test conditions" select inside `#board-shape-field`, with accuracy and date; `#board-bests-meta` gives the shape's full conditions, and `#board-bests-none` replaces the picker, that line and the list when nobody on the board has a comparable best; custom-text runs count in none of the three lists), each an ordered list of `.board-row` items (`.board-name`, `.board-value`, `.board-detail`); your own row is `[data-self]` and reads "You". `#board-daily-meta` and `#board-week-meta` name the date and rule. Rows come only from mutual friends and carry the name on your own list. `#refresh-friends-board` reloads (aria-disabled while loading, so it keeps focus), `#friends-board-status` reports loading, failures and "Updated." after a Refresh, and `#friends-board-empty` (with `#friends-board-online`) explains how friends get there when nobody else is listed. Each row shows exactly the summary that account's own profile row holds: every profile save writes it into the row's `board` column (never for guests), so a clear or undo reaches the board with its save, as in Progress. Each run counts in its own day and week (a daily by the date it was played for, practice by when it was run), never by the writing device's clock. Turning sharing on rewrites the row's summary if saves made while an opt-out was unconfirmed left it without one. The board only reads, and an open board reads again, quietly, after each profile save of this tab. A board left open reads again, quietly, once the service's next 00:00 UTC has passed (so Monday's new week too), `nextDay` seconds after the last reply arrived by the device's clock or the page's monotonic clock, whichever passes first, from the 30-second day check or when a hidden tab returns: no loading line, no "Updated.", and no failure line (a failed read is tried again at the next check). Only opening the board and Refresh report loading and failures, and the status line is written only when its words change, so a screen reader never hears the same line twice. A daily result from another build reads "another version of the daily · not compared". The shape picker lists only keys this build writes, opens on the shape the viewer has the most completed tests and retests on, and keeps a pick across re-reads; a best on the same shape from another build reads "another version of this shape · not compared", and someone without one "no best on this shape yet". See [online races](online-races.md#friends-board-9-october-2026).

## Local challenge

Required IDs: `compete-setup`, `player-one-name`, `player-two-name`, `start-local-race`, `race-stage`, `race-player`, `race-status`, `race-handoff`, `handoff-name`, `handoff-veil`, `start-next-player`, `race-text-display`, `race-accessible-passage`, `race-input`, `race-help`, `race-progress`, `race-leaderboard`, `race-winner`, `race-results`, and `race-again`.

The two players type the same original passage sequentially on one keyboard, using the correction policy captured when the challenge starts. Mirror that passage into `#race-accessible-passage`; `#race-input` includes it in `aria-describedby`. `#race-progress` is a progressbar whose first child fills from `--progress`. Before player two starts, `#race-handoff` hides the passage and asks the players to hand over the keyboard; `#handoff-name` names the next player, and `#handoff-veil` is aria-hidden decoration that must keep the passage illegible. Do not show online presence, ratings, or fabricated opponents. The result compares corrected WPM, input accuracy, and elapsed time from the two observed attempts.

## Progress and local history

Required IDs: `history-list`, `history-row-template`, `progress-empty`, `clear-history`, `clear-dialog`, `confirm-clear-input`, `confirm-clear`, `cancel-clear`, `history-toast`, `undo-clear`, and `history-feedback`.

`#standard-score` heads Progress on every profile, above `#progress-empty` and `#progress-content` and never hidden with them, so a fresh profile can reach `#take-standard`. It shows the current standard recipe at one input class, chosen by `standardInputClass` in `src/insights.js`: physical keyboard by default; touch only when the keyboard has no kept standard run and no best while touch has either, or when touch has a median (three kept runs) from more kept standard runs than the keyboard. Kept run counts are not lifetime counts (bests outlive the newest 1,000 summaries), so one touch run never hides a keyboard best. `#standard-best` (the stored best), `#standard-median` and `#standard-median-label` (the median wpm of the newest completed standard runs, up to ten, shown only from three kept runs), `#standard-score-note` (the count of kept completed standard runs, worded as kept and never as a lifetime count, plus a sentence when the best is above every kept run and so comes from an older one; or why there is no median yet, including when the best outlives every standard run in the newest 1,000 summaries; then the other input class's best in one sentence when it has one), `#standard-score-conditions`, and `#take-standard`.

`#progress-empty` is visible when no completed loop exists and links back to Practice. History rows state mode, text/corpus conditions, metric version, and sample counts. `#clear-history` opens the typed-confirm dialog. The confirm button stays disabled until the exact word `clear` is entered. After clearing, show `#undo-clear` in `#history-toast` for five seconds.

## Accounts

Required IDs: `account`, `account-trigger`, `account-guest`, `account-create`, `account-google`, `account-signin`, `account-member`, `account-email`, `account-sync`, `account-signout`, `account-dialog`, `account-form`, `account-dialog-title`, `account-dialog-copy`, `account-dialog-google`, `account-email-input`, `account-password`, `account-error`, `account-switch`, `account-cancel`, `account-submit`, `account-confirm`, `account-confirm-email`, `account-confirm-done`, `account-toast`, `account-feedback`, `guest-note`, `account-delete`, `delete-account-dialog`, `delete-account-form`, `confirm-delete-input`, `delete-account-error`, `delete-account-status`, `cancel-delete-account`, and `confirm-delete-account`.

`.corner` holds `details#inbox` and `#account` top right; between 761 and 1023 px the inbox sits under the account button so the pair clears the dock. `#inbox` (members only) has `#inbox-trigger`, the unread count `#inbox-count`, `#inbox-list` entries with `[data-inbox-action]`, `#inbox-empty` and `#inbox-clear`. `aside#challenge-toast` (`#challenge-toast-text`, `#challenge-toast-action`, `#challenge-toast-close`) drops in under the corner for a new challenge or rematch and leaves after 18 s, held on hover or focus, and waits while a run is in progress.

`#account` is a `details` menu fixed top right (it scrolls with the page on mobile, where the dock is at the bottom) and fades with the chrome while a run is in progress. `#account[data-state]` is `guest` or `member`; `#account[data-sync]` is `guest`, `syncing`, `synced`, `offline` or `expired`. Guests see the three sign-in choices and `#guest-note` in the footer; nothing is written to storage for them. Email sign-up that needs confirmation shows `#account-confirm` instead of the form. Signing in or out reloads the page as the new user.

Members also see `#account-delete`, which opens `#delete-account-dialog` (also reachable as "delete account…" in the palette). `#confirm-delete-account` stays disabled until the exact word `delete` is entered in `#confirm-delete-input`; while the deletion is under way (at most 30 s in all, one deadline shared by the session refresh, the function call and the account check) it reads "Deleting…", `#delete-account-form[aria-busy]` is true, `#delete-account-status` says so to screen readers and the dialog cannot be dismissed. Closing it returns focus to `#account-trigger` when it was opened from the menu. A failure is written to `#delete-account-error` (a live alert) and changes nothing. Success clears the account from the device and reloads as a guest; `#account-toast[data-tone="done"]` then says the account was deleted, once.
## Learn to type

`#learn-screen` holds the beginner path. `#lesson-current` shows the next lesson, the last lesson result in this tab (`#lesson-status`, `#lesson-current-heading`, `#lesson-facts` with each target and a met / not met word) or the hand-off once every letter is in. `#lesson-primary` is the one filled-green action (start the next lesson, try again, or take a practice run) and takes focus after a lesson finishes; `#lesson-secondary` is a ghost action. `#lesson-keyboard` is the finger map (`role="img"`, with every finger's keys in its label), and `#lesson-list` has one row per lesson with `data-state` `passed`, `next` or `locked`. A lesson runs on the shared typing surface with `data-session="lesson"`; `#keyboard` then shows the same finger map whatever the keyboard setting. Lesson runs never enter `runs`, `attempts`, `bests` or `seenTextIds`; their progress lives in `profile.lessons` (src/lessons.js).

## Ghost pacer

`src/egg.js` listens for ↑↑↓↓←→←→ b a; typing `ghost` in the palette offers the same toggle. `body[data-ghost]` is `on` or `off`. When on, `.ghost-caret` moves at the personal best for the current conditions (or 60 wpm). `#egg-toast` / `#egg-feedback` confirm the change and it is announced. The ghost is presentational only and never scored.

## Accessibility and sizing

All controls are reachable by keyboard and use one focus ring (the accent outline). Mobile interactive targets are at least 44 px. The skip link targets `#typing-input`. Status updates use `#announcement`. IME composition, paste, touch-only input, and focus interruption are announced and displayed in `#input-help`; accent (dead) key compositions on `#typing-input` and `#race-input` are scored as the one or two characters they commit. A composition is an accent key's only if one opened it: its `Dead` keydown, before the mark shows or (Safari) just after, or a lone accent mark shown first, which is all Chromium on Linux gives (its keys arrive as `Process`). Any other composition, even one that commits a single Latin letter (Pinyin, Telex), is refused as IME text, as is a preview or commit no Latin keyboard key produces (another script's letter, digit or punctuation, CJK, kana, full-width, an emoji, more than a mark and a key; a Latin layout's own symbols, such as ’ — ⁴, still type) and a change to letters already typed such as the press-and-hold accent menu. Every key of a commit is scored before the passage can end; one carried past the last letter (`"h` on a closing `"`) is a mistake against that letter, is not kept, and shows as extra in the result's character breakdown, while one that is that letter (`""`) adds nothing; a Windows mark sent as an input of its own waits for the next key's input, so the pair is scored together there too. A held accent key's repeats are ignored like any key repeat (including the `Process` repeats Chromium on Linux sends), as is the letter that commits a mark it left pending, while another accent key pressed during the hold, or after the key is let go out of the field (focus elsewhere, a finished run), types as usual; a mark still pending when focus leaves is dropped; custom text takes accent keys like any other passage, and a commit made before a timed run's limit is scored even when its key arrives after the limit; interrupted attempts are never stored as comparable results. All motion scales to zero under `prefers-reduced-motion`.
