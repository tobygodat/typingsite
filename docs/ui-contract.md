# UI contract

This document is the integration contract between the static interface in `index.html` and the behavior in `src/app.js` (with `src/motion.js`, `src/graph.js`, `src/palette.js` and `src/egg.js`). The app is a single document with one shared typing surface so practice, targeted drill, and fresh-text retest preserve the same geometry and input behavior.

## Screen model

- `body[data-view]` is one of `practice`, `results`, `train`, `progress`, `compete`, or `learn`. `learn` has no dock item; it opens from `[data-action="open-lessons"]` (the quiet "learn to type" link in the practice controls and the first-run links) and the palette.
- Only the matching `[data-screen]` is visible. Navigation controls use `[data-nav]` with the same values and set `aria-current="page"` (and `.is-active`) on the active item. The dock labels them practice, train, progress and challenge; the brand link also navigates to practice.
- `#typing-screen` is the shared typing surface. Its `data-session` value is one of `practice`, `drill`, `retest`, `daily`, or `lesson`; `body[data-session]` mirrors it for styling.
- Train, progress, and challenge use `#train-screen`, `#progress-screen`, and `#compete-screen`.
- `body[data-running]` is present from the first keystroke of a run until it finishes or restarts. While it is set, chrome other than the passage and its measure row fades out; pointer movement, finishing or restarting brings it back. It never changes the passage geometry.
- Buttons with `[data-action]` expose intent for delegated event handlers. All navigation and state changes happen without a page reload.

## Theme

`html[data-theme]` is `dark` or `light`. An inline script in `<head>` resolves it before first paint from `preferences.theme` in the `stilltype-profile-v2` profile, falling back to `prefers-color-scheme`. The stored preference is `system`, `dark` or `light`; `system` follows the OS and updates when it changes. `meta[name="theme-color"]` is kept in step with the resolved theme.

## Quote filters

Quote filters use the select-only comboboxes `#quote-length` (labelled "length") and `#quote-difficulty` in `#quote-options`. Each label, current value and chevron is one 44px target with natural text width. Their opaque absolute listboxes do not change the rail layout. Arrow keys, Home, End and typeahead explore a draft; Enter or Space commits and focuses practice. Escape or the same trigger cancels. Tab, Shift-Tab and outside clicks commit without moving focus away from the destination. Selecting the current value closes without restarting. Only one quote or more menu opens at a time. Book mode's `#book-options` uses the same combobox, `#book-select` (labelled "book", the label visually hidden), followed by `#book-page` ("page N"). Preference refreshes, mode/view/focus changes, resize, window blur and commands dismiss the draft. Settings selects remain native.

## Dock, settings and command palette

The dock (`nav.dock` in `.dock-zone`) holds the brand link, the `.dock-nav` view buttons, the settings popover (`details.preferences`, whose `summary.dock-settings` shows an icon and the label "settings") and `#palette-trigger`. The popover is positioned against the dock: below it on desktop, above it on mobile. Restart (`#restart-button`) stays in the typing footer.

The collapsed `#test-content-settings` category contains `#word-list`, `#numbers-toggle` and `#repeat-quotes-toggle`. Numbers default off, apply only to time/word tests, and remain available through the "numbers" command. They are recorded in run conditions, keeping bests and retests separate from runs without numbers. Quote and daily passages ignore the preference. The passage mode bar has no numbers control.

Selection pills: a `.glide` container with `data-glide="current"` follows `aria-current`; `data-glide="pressed"` follows `aria-pressed`. Its `.glide-pill` is aria-hidden decoration; state always lives in the ARIA attributes and `.is-active`.

Settings are `#theme-select` (`system`, `dark`, `light`), `#font-size` (`22`, `28`, `36`), `#typing-font` (`literata`, `source-serif`, `inter`, `jetbrains-mono`, `ibm-plex-mono`, `roboto-mono`, `fira-code`), `#app-font` (`literata`, `source-serif`, `inter`), `#speed-unit` (`wpm`, `cpm`), `#word-highlight` (`off`, `current`, `next`), `#word-list`, `#repeat-quotes-toggle` (both in the test content category), `#live-toggle`, `#keyboard-toggle`, `#tape-toggle`, `#correction-select`, `#min-accuracy` (`0` off, `80`, `90`, `95`, `98`) and `#min-wpm` (`0` off, `20`–`100`) sharing one `minimums` row, `#focus-toggle`, `#train-focus` (`balanced`, `accuracy`, `speed`), `#drill-length` (`15`, `30`, `60`, `120`) and `#retest-toggle` (`true`, `false`), `#sound-select` (`off`, `clicks`, `clicks-errors`) and `#sound-volume` (a 0–100 range in `#sound-volume-row`, disabled while sound is off, with its value in `#sound-volume-value`); `#exit-focus` sits outside the dock. While a minimum is set, `#minimum-note` names it on its own line under the practice controls; it is hidden while Custom or composing is open, a custom passage is loaded or the standard test is selected, since those runs have no minimums and run to the end. Apply theme as `html[data-theme]`; font size as `body[data-font-size]`; word highlight as `body[data-word-highlight]`; the one-line tape as `body[data-tape]` (the layout on screen: `false` during a ghost race, which keeps three lines whatever `#tape-toggle` says); live metrics as `body[data-live-metrics]`; keyboard as `body[data-keyboard]`; focus mode as `body[data-focus-mode]`. `#correction-select` picks the correction policy (`CORRECTION_POLICIES` in `src/typing.js`): `relaxed` ("free", the default: mistakes can be typed through and fixed), `mandatory` ("stop on error": the caret waits on a wrong letter), `no-backspace` (mistakes stay; backspace does nothing), `fail-word` (a word left wrong at a space or the end fails the run) and `fail-any` (any wrong key fails the run). Profiles that stored the old boolean `stopOnError` map to `mandatory` or `relaxed`. Changing the correction policy starts a new practice run. The policy is stored in run conditions, keeping bests and comparisons separate. Repeat quotes (`preferences.repeatQuotes`, off by default; also the palette command "repeat quotes"; both disabled outside quote mode) lets open quote practice draw a quote the profile has already seen. Turning it off replaces an unstarted repeated passage with unseen text, at once on Practice and otherwise when Practice next opens. Such a passage is `fresh: false`: `#input-help` says so before and during the run, and the result is labelled repeated text and compared only with earlier runs on the same passage. Repeated text never sets a best, enters trends, weekly medians or pattern evidence, or becomes either side of a retest; retests always draw unseen text. The speed unit is display only: every speed is saved, scored, compared and keyed in wpm, and shown in the chosen unit (cpm = wpm × 5, `src/units.js`). Each speed figure the app writes is a `<data>` whose `value` and `data-wpm` hold the wpm, and unit labels carry `data-speed-unit` (empty for the bare unit, otherwise a `{unit}` template). The raw speed tooltip (`#result-raw-row`) is worded for the chosen unit. Speeds a person sets are shown and entered in the chosen unit and saved in wpm: `#min-wpm` option labels, the palette's minimum speed commands, and `#pace-wpm` (its value, bounds, step and `#pace-range`, all in the unit in its `data-unit`, which an unsaved pace being typed keeps until the field is left; a saved pace, Enter included, reads back at once as the figure saved; a typed cpm is saved as the nearest whole wpm). A minimum speed reads in the chosen unit wherever it is named (conditions line, run card note, Progress detail); changing the unit redraws the figures already on screen (toasts included) without starting a new run, closing open Progress rows or moving focus. A figure inside a showing live region may be read out again in the new unit; that is accepted, since a unit change is almost always the person's own and one synced from another device mid-session is rare. A synced change held back through a run applies as it ends, and never stops that run's result being written to its live region. The generated keyboard belongs in `#keyboard`. The default Escape binding exits focus mode before restarting on a later press. Strict space (off by default) refuses a space where the passage has a letter, scoring it as a wrong key without moving the caret and tinting the skipped letter until the next key. Quick end (on by default) ends a continue-on-error word or quote run on its last letter; off, a mistake in the last word waits for a fix or a space. What a session can take comes from that session (its kind, timing and run conditions), not the test-shape preferences: `#quick-end-toggle` is disabled, keeping its value, wherever quick end can't change the run (timed runs, including every drill, and stop on error), and `#quick-end-note` says why. A change on the practice screen restarts the session as the same kind; the daily and a retest keep the rules they started with, carry on, and `#rules-note` (read by both switches) says so. On the Challenge screen's One keyboard tab the session is the race, an untimed quote whatever the practice shape: the switches act on the next race, and a race under way keeps its rules for both players and says so. Starting a retest or drill restores its baseline's test shape but never writes its rules into these switches: a retest takes them for its own conditions, and the person's choice waits for the next run it applies to. Other screens stay put, and a practice passage left waiting there is rebuilt when practice is shown again. Both enter run conditions only when they differ from the defaults and apply to the run. `#layout-select` (`qwerty`, `dvorak`, `colemak`, `colemak-dh`, `workman`; from `src/layouts.js`) sets the keyboard legend and is recorded as `layout` in run conditions; changing it starts a new practice run. Typed characters are never remapped. `#finger-toggle` sits in `#finger-row`, which is shown only while the keyboard is on; below 760px both keyboard rows are hidden with the keyboard. `#keyboard` carries `data-layout` and `data-fingers`; each `.key` carries `data-key`, `data-hand` and `data-finger`; the finger map draws each finger's initial as aria-hidden generated text, gives each key one spoken phrase naming its hand and finger (an aria-hidden printed cap plus `.sr-only` text such as "f, left index"; keys are plain letters while the map is off) and adds a `.finger-legend`. Retests and drills never change the layout; a physical-keyboard baseline typed on another layout is refused for retest. Touch runs record the default layout and are never refused for it.


The configurable exit-focus shortcut or `#exit-focus` exits focus mode; Escape does so by default.

The command palette is `dialog#palette`. `#palette-input` is a combobox controlling `#palette-list` (a listbox rebuilt from the app's commands on every keystroke, so hints show current state); `#palette-empty` shows when nothing matches; `.palette-highlight` is aria-hidden. The commands binding (Ctrl-K / ⌘K by default) and `#palette-trigger` open it; Escape closes it and returns focus. Opening it closes settings, and opening it during a run marks that run interrupted.

## Shared typing surface

Required IDs: `typing-screen`, `typing-form`, `typing-input`, `typing-wrap`, `text-display`, `accessible-passage`, `live-stats`, `live-wpm`, `live-accuracy`, `timer`, `timer-unit`, `timer-label`, `progress-track`, `progress-bar`, `typing-status`, `session-kicker`, `session-title`, `session-description`, `condition-line`, `input-help`, `restart-button`, and `announcement`.

`#text-display` receives `.word > .char` spans. Character state classes are `.correct`, `.wrong`, and `.current`; they change instantly, without transition. `.wrong` always has a non-colour tint; on a space it is painted at full line height so the row keeps an even band. Under `forced-colors: active` it switches to the system `Mark` / `MarkText` highlight so the mark survives the forced palette. Every rendered passage (`#text-display`, `#race-text-display`, `#online-text-display`) also marks the `.word` holding the caret `.word-current` and the one after it `.word-next` (a space belongs to the word before it); `body[data-word-highlight]` decides which, if either, shows the `--word-highlight` tint. Like the letter states it changes instantly, without transition, and is never scored. Watch replay (`#replay-dialog`) and the composing field have no current word and never show it. The display has a fixed three-line height (one line with `body[data-tape="true"]`); live metric updates must not change its geometry. `src/motion.js` inserts only two aria-hidden elements into the display after each render, `.caret` and `.ghost-caret`, drives the ~150 ms line scroll (or the tape's word-aligned steps, from `src/tape.js`), and sets `data-caret` / `data-blocked` (and, for the tape, `data-tape-scrolled`) on `#typing-wrap`.

`#typing-input` is the real focus target and remains visually transparent over the displayed text. `#progress-track` is a thin line with `role="progressbar"`; keep `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, and `aria-valuetext` current. `#progress-bar` fills from its `--progress` custom property (0–1), not its width.

`#live-stats` is plain text and is not a live region; update it at a restrained cadence. Completion is announced once through `#announcement`.

Practice mode controls are `#mode-time`, `#mode-words`, `#mode-quote`, `#duration-options`, `#punctuation-toggle`, `#quote-options`, `#quote-length`, and `#quote-difficulty`. The four preset length buttons in `#duration-options` carry `data-length`, are relabelled in place when the mode changes (never rebuilt) and use `aria-pressed`. `#custom-length`, the last pill, reads "custom" or the custom value in use; pressing it hides it and shows `form#custom-length-form` with `#custom-length-input` in its place (`.practice-controls[data-editing]` while open, which also shows the row in focus mode). Enter, or leaving the field with a valid value, applies it; Escape restores the pill; pressing another control in the row drops the edit. In focus mode, where the row hides again as the field closes, focus that would land in the row goes to `#typing-input`. Invalid input sets `aria-invalid` and a message in `#custom-length-error` (`role="alert"`), positioned in the gap under the row so the passage never moves; the message stays visible in focus mode and clears when the next run starts. The palette commands "custom time…" and "custom words…" open the same field.

Practice mode controls are `#mode-time`, `#mode-words`, `#mode-quote`, `#mode-standard`, `#mode-book`, `#duration-options`, `#punctuation-toggle`, `#quote-options`, `#quote-length`, and `#quote-difficulty`. Generated length buttons belong in `#duration-options` and use `aria-pressed`. `#mode-compose` sits in the same group (`data-compose`, not `data-mode`) and opens composing practice.

`#mode-standard` selects the standard test: one fixed, versioned recipe (`STANDARD_VERSION` in `src/typing.js`, now `standard-v1`) of 60 s, stop on error, sentences from the 1k/5k/10k word bands with punctuation and numbers, the second of them in quotation marks as the quote segment. Every word, the quote's included, comes from the attempt's own seed (`standardPassage`), recorded in the text ID, so no attempt repeats text from the quote corpus or an earlier attempt. On layouts where `"` is a dead key, browsers report composition, which isn't scored, so those typists need #61 (dead-key input) to complete a standard run. Its conditions carry `recipe`, which `conditionKey` appends only when present, so it has its own bests, trends and retests. While it is selected, `#standard-options` (with `#standard-recipe`) replaces the length buttons, and `#punctuation-toggle`, `#word-list`, `#numbers-toggle` and `#stop-on-error-toggle` are disabled with the recipe's values (numbers on) and, in settings, a `.preference-lock` note; the palette leaves out the punctuation, numbers and word list commands. Standard conditions carry no `numbers` field, since the recipe fixes them, so standard keys are unchanged by the numbers toggle. `#word-list` gains its recipe option (`standard`) only while standard is selected, and `setWordList` accepts only real list IDs; the person's own settings are kept for the other modes.

## Composing practice

`body[data-compose="true"]` while composing is open: `#typing-form` is hidden and `#compose-form` (`data-state` `ready` or `done`) takes its place on the practice screen; the length options and `#punctuation-switch` are hidden and the footer best is hidden. The form holds `#compose-prompt`, `#compose-conditions`, `#compose-another`, `#compose-timer`, the free-typing `#compose-input` (described by the prompt, `#compose-hint` and `#compose-privacy`), the `#compose-progress` progressbar, `#compose-help` for notices, `#compose-restart` and `#compose-done` (Ctrl/⌘+Enter). The result is `#compose-result`: `#compose-result-heading`, `#compose-wpm`, `#compose-backspace`, `#compose-active`, `#compose-characters`, the definition `#compose-definition`, `#compose-saved`, `#compose-retry` and `#compose-next`, which takes focus on finishing. Escape in the field starts over. Where `CSS.supports('caret-animation', 'manual')` is false, `src/compose-caret.js` sets `data-caret="drawn"` on `.compose-wrap`, which makes the field’s native caret transparent, and inserts one aria-hidden `.compose-caret-layer` after the field, holding an empty hidden mirror and the `.compose-caret` bar (no animation or transition, `hidden` unless the field is focused, writable and has a collapsed selection); otherwise it adds nothing. Choosing time, words or quote, a drill, a retest or the daily ends composing; settings and sync wait until it ends. Progress lists saved sessions in `#compose-history` (`#compose-history-note`, `#compose-history-list`), apart from the copy-test charts. Only numbers are stored, never the text.

`#best` in the footer shows the personal best for the conditions of the session on screen, or states that there is none: the daily's and a retest's own conditions (a retest's rules are its baseline's, whatever the switches say now), otherwise the current settings; custom text says it isn't counted. `#suggest-trigger` beside it (and the palette command "suggest a feature…") opens `dialog#suggest-dialog`: `#suggest-text` (max 1000 characters, counted in `#suggest-count`), errors in `#suggest-error`, a hidden honeypot `#suggest-website`, and `#send-suggest`, which inserts `{ body, view }` into the Supabase `feature_suggestions` table through `sendSuggestion` in `src/account.js`, always as the anonymous role (a filled honeypot sends nothing). Success closes the dialog and shows `#suggest-toast`; failure keeps the text. Opening it mid-run marks the run interrupted, like the palette.

## Completed run and recommendation

`#results-heading` contains `#result-delta`, the one-line headline for the run. `#result-comparison-note` stays empty except for interrupted-run and storage messages.

The run card is `#run-card`: `#speed-graph` (an SVG speed-over-time graph drawn by `src/graph.js` from the attempt's keystrokes, mistakes in coral; `role="img"` with a text summary in its `aria-label`; presentational only), `#result-wpm`, `#result-accuracy` (its fact `#result-accuracy-fact` titled with first-try errors and the final c/i/e/m), `#result-time`, `#result-consistency`, `#result-standing` (average and best at these conditions, hidden before a second counted run), the words `#result-words` with `#result-word-detail` (the chosen word's pace, empty before a choice), `.result-actions` (Run again, the drill, Watch replay and `#result-conditions`) and, after a run that counts as evidence and has missed or timed words (a complete test, retest or daily run, by the same rule as recurring patterns; never a drill, a daily passage shown before, custom text or word practice itself), `#practice-words` (the missed words are the coral ones in `#result-words`; this run's slowest clean words join them), which starts an uncounted `missed` practice run of those words. That run becomes the baseline for the fresh retest offered afterward, which reads and records no drill target. The card is a static print: numbers are set directly, with no tilt, reels or count-up.

Patterns across runs (`section.training-memory` in Progress's keys view) lists the learner's queue at the keyboard of the conditions picked in `#training-conditions`, in the train focus: up to 8 `.training-target` rows, each with Train's heading and evidence line for that unit, its last drill when there is one, and "Practice “…” again". The first row is the target Train names. Below it, `section.missed-words` lists the words you keep missing: `#missed-words-note` names what was counted (the newest counted runs that recorded missed words, up to 120 and up to 12 words each: complete tests, retests and new daily passages, the runs pattern memory reads, so never word practice, custom text, drills, interrupted runs or a daily passage shown before; only those on the newest such run's input class, since touch is never pooled with a physical keyboard), or says plainly that there isn't enough evidence yet and how much there is. With two or more words missed on the first try in at least two of those runs, `ol#missed-words-list` shows up to 8 (`li.missed-word`: the word, then "missed in N of the last M runs") and `#practice-missed-list` (accessible name "Practice these N words you keep missing", apart from the run card's button; also the palette command "practice words you keep missing") starts the same uncounted `missed` run with those words. Pressed over a list the runs no longer match (changed by a sync or another tab), it redraws the list first and practises the words the runs hold now; with fewer than two left it starts nothing, announces that and moves focus to `#missed-words-heading`. Clearing history empties the list, and Run again after it starts a normal test.

The manual target lives in `details.manual-panel` (summary `#manual-heading`): `#manual-target` form, `#manual-target-input`, and `#apply-manual-target`. It accepts a short letter pair or word. Validation appears in `#manual-target-error`; invalid state uses `aria-invalid="true"` and visible recovery copy.

## Train

Train is a path (TOB-420): the targets you have drilled behind you, the one to drill now, and the next ones the learner queues, on one line. `trainPath` in `src/train-path.js` builds it as a pure function of the profile's runs and loops, the learner's recommendation in the train focus (`recommendFor`), and, after a retest, the unit just retested: `{ behind, just, current, ahead }`. The page draws exactly what it returns. The same profile and settings give the same path on any device, and after a merge in either order.

- **No visible heading.** The dock names the page. `#train-heading` is visually hidden (`.sr-only`, focusable with `tabindex="-1"`) and holds the open step's title ("Practice “th”", or "General drill"). A palette jump to Train focuses it.
- **The line.** `ol#train-path` (accessible name "Path"), one `li.path-step` per step: `.is-behind` (with `.is-drilled` or `.is-fixed`), `#train-current` (`aria-current="step"`), and `.is-ahead`. Each step has a `.path-head` (its `.path-node` and `.path-unit`) and `.path-line` evidence. A step behind you says "drilled" or "fixed" in a status word, `.path-status`, beside its target. In the evidence a figure keeps its number with its unit, and a before → after pair wraps only between its halves (`.path-figure`). From 901px the steps sit in columns, six to a screen with a gutter between them, and when there are more the list scrolls sideways: it opens scrolled to its end, takes `tabindex="0"` only while it scrolls, and the arrow keys scroll it. While more of the line lies past an edge (`data-more-behind`, `data-more-ahead`), that edge fades, and at the start the tail of the next step behind you shows there, so the first whole step stays clear. Up to 900px the line runs down the page and shows the two newest steps behind you; Progress keeps every drill.
- **The open step** (`current`). Fresh, it is the learner's target, the head of its queue, so Train, the results card's Drill, the comparison's Next and Patterns across runs agree. Its details are `#train-next`: `#train-evidence` (the learner's observed evidence, `evidenceCopy`: misses for a unit named on its misses, pace for a pair named on its pace; "across all N runs" once it has been drilled), `#train-last` (its "since you drilled it" line, before → since, when it has a loop, of the kind of evidence the step is drawn for, whatever its drill was for), `#train-words` (below), then one button and `#train-starts`, which says what the button starts ("30 s, then 10 words on fresh text", or "30 s" when no retest follows). With nothing named it is the general drill, `#train-unit` reads "General drill", nothing is queued ahead, and three empty places (`.is-place`, `aria-hidden`) run on from it.
- **The button.** `#start-drill` drills the open step: "Drill “th”" for a named unit, "Drill and retest" for a general drill when a retest follows, and "Drill" when none does (the retest is off, or there is no baseline). After a retest with a named next unit it is `#comparison-next` ("Next: “an”"), which drills that unit through `practiceTarget`, so the loop records the policy and focus that queued it.
- **Steps ahead** (`ahead`). The next three units in the queue, each a `button.path-choose` (accessible name "Drill an, 5 of 40 missed", or "Drill th, 120 ms slower") with its evidence: "N of M missed" or "N ms slower". Choosing one drills it through `practiceTarget`, as Next does. No unit is both behind you and open or ahead.
- **Steps behind you** (`behind`). One per target with a loop on this keyboard, at its newest loop, oldest first. Each shows the loop's own read-back ("6 of 22 → 1 of 12 missed", or "70 ms slower → 20 ms faster"), and once two runs since the drill hold observations of the kind it was drilled for, what they show ("0 of 36 missed since the drill", or "13 ms faster since the drill, over 36 intervals"). A loop saved before the read-back existed shows its before and since figures ("40% → 10% missed since the drill"). A drill with the retest off saves no loop, so it is never behind you.
- **Drilled and fixed.** One retest makes a target drilled. A target behind you is fixed when the learner no longer queues it and at least two runs since its drill hold observations of the kind it was drilled for (first tries for a target drilled for its misses, clean intervals for a pair drilled for its pace), at least 20 of them between those runs, with no first-try miss among them, or a mean slowdown of 20 ms or less. Otherwise it is drilled. (`isFixed`, `FIXED_RUNS`, `FIXED_OBSERVATIONS`, `SLOW_FLOOR_MS`.) A run that holds the pair but no observation of that kind (a pair typed only with a typo beside it, so never timed) is not one of the two. A fixed target the learner names again leaves the steps behind you for the open step or the steps ahead.
- **After a retest.** The comparison, `li#comparison-panel`, is the newest step behind you (`just`), drawn from the comparison rather than a loop, spanning two columns from 901px, and the open step is the first unit queued after the one just retested. Its label `#comparison-unit` is the unit, or "General drill", "Adaptive", or "Retest" for a retest whose drill named no unit. `#comparison-status` (the outcome sentence, with a status dot coloured by `data-outcome`) takes focus; Tab then reaches the open step's button and `#comparison-back`. The path moves on one step as it opens (`.is-advancing`: the steps slide one column left, the open step's details fade up, `--dur-fast`, none under reduced motion). Opening Train again draws the path afresh at your settings.
- **Following the history.** Any change to the history this tab holds (a merge from another tab or device, a clear or its undo, here or elsewhere) goes through `followHistory`, which redraws every training surface on show through `showTraining`: Train's path, the results card's Drill, the comparison's Next, Patterns across runs, Progress's lead and what moved it, and the lessons' hand-off. A clear that removes the comparison's runs takes the comparison and its Next away, and the path opens on the cleared history. Mid-run nothing changes; the surfaces follow when the run ends. A redraw keeps keyboard focus on the step that had it, or gives it to the open step's button when that step is gone, and keeps the line scrolled as far from its end as it was.

`#train-words` lists missed words that hold a target named for its misses, the target in the text colour and the rest muted, never coral (where in the word the miss fell isn't kept); a pair named for its pace lists none.

## Drill and retest

`#start-drill` changes the shared typing surface to `data-session="drill"`; the page uses the same input and text display with target-heavy generated text. The drill runs the length `#drill-length` set when it started (30 s by default; `#session-kicker` reads "drill · N s"). With `#retest-toggle` off, `#start-drill` reads "Drill", the drill ends on its own result card with nothing compared, and no loop is saved. The train focus, the drill length and the retest are preferences, never test conditions, and are also palette commands ("train focus · …", "drill length · N seconds", "retest after drill"). Every surface that shows what Train would drill (the run card's `#result-drill`, Train's path with `#start-drill`, the comparison's `#comparison-next` and the steps ahead, Patterns across runs) asks the recommender again when one of them changes, here or by sync from another device, and its button drills what it shows; the loop records the focus that ranked it. A plain passage is kept, so the plain test that follows an adaptive run stays the baseline it was drawn to be. The lessons' hand-off, which states the drill's length and whether a retest follows, is redrawn with them. A drill whose history another device cleared while it waited still runs, shows and records the length it was drawn with. ## Progress and local history

Progress answers one question first: what changed since last week, and what moved it (TOB-420). `weekChange` in `src/week-change.js` builds the overview as one value, a pure function of the profile's runs, loops and practice days, the chosen condition key, the train focus, the daily goal, the period and `now`: `{ lead, movers, practice, charts, recommendation }`. The page draws what it returns. The same history and settings give the same overview on any device, and after a merge in either order.

Required IDs: `history-list`, `history-row-template`, `progress-empty`, `clear-history`, `clear-dialog`, `confirm-clear-input`, `confirm-clear`, `cancel-clear`, `history-toast`, `undo-clear`, and `history-feedback`.

- **No visible heading.** The dock names the page. `#progress-heading` is visually hidden (`.sr-only`, `tabindex="-1"`); the palette's jump to Progress focuses it. `#progress-screen[data-detail]` is empty on the overview and names the detail view otherwise.
- **The lead** (`#week-lead`, `data-state` and `data-tone`). This week is today and the six local days before it; the week before is the seven days before those (`weeklyChange`), each run in the week of the day it was typed on (`runDay`). Only fresh-text practice runs and retests at the chosen key count, and a week has a median only from `WEEK_MIN_RUNS` (3) runs. `change`: `#lead-figure` is the change, the difference of the two whole medians printed in `#lead-sentence` ("78 this week, 75 the week before"), in the accent for a gain, in coral for a drop, plain for none, with its unit and a visually hidden sentence ("5 wpm faster than the week before"); `#lead-sample` gives both run counts. `this-week`: the figure is this week's median, and `#lead-note` gives the week before's run count when it has runs but too few for a median (hidden when it has none). `last-week`: the week before's median, and `#lead-note` gives this week's run count. `thin`: the latest run's speed, and `#lead-note` says a week has a median from three runs. The note states counts and the rule only: it never predicts a day a change will show. `none`: no runs at these conditions in two weeks. A unit change redraws the lead in place.
- **The conditions control.** `details.conditions-disclosure` in `#progress-filters`: its summary is the conditions line (`#lead-sample`, `#progress-conditions`, a chevron), and opening it shows `#progress-tests` (one pill per length, a length without runs disabled) and, when a length has several condition sets, `#progress-variants`. The lead, the charts and every list read that one key, and conditions never mix; the line names the corpus and metric version where the sets beside it differ by one. The newest run's length opens, on its most used set.
- **What moved it** (`ol#week-movers`, accessible name "What changed since last week"). One `li.mover` per unit (`data-unit`, `data-status` `fixed` or `slipping`): the unit, its before → after figure of one kind of evidence (misses as "N of M", or pace against the person's own, never a zero or negative amount as slower) with the sample in its title, a status word, and for a slipping unit `Drill “…”`, which starts a drill through `startDrill` recording the policy and focus that ranked it. The movers read every measured run on the chosen key's keyboard in the train focus, as Train does. "A week ago" is the learner built on the history as it stood when this week began. Fixed is Train's `isFixed`: a drilled unit since its drill (so Train shows it fixed too), a unit never drilled that the learner named then and doesn't now, since this week began. Slipping: named now by the learner, whatever for, read on 20 tries or more before this week began and 20 or more since over two runs or more, and missed more since than before, by more than noise and by more than the week as a whole. The test asks how often, had this unit's odds of a miss changed only as the rest of the week's typing did, that many of its misses would fall since (Fisher's exact test, one side, against the week's own odds ratio: `chanceOfRise`, `weekOdds`). The week's odds ratio is read from every other pair's tries and misses on each side (keys left out, since they hold their pairs' misses again), each side's rate leaning on the pooled rate with the weight of 20 tries, and is never read as an improvement. So a bad day that raises every pair is no slip of any one of them. Every unit read on both sides is such a question (`slipFamily`), and the more someone types the more there are, so each is held to `SLIP_CHANCE` (2 in 100) divided by their number. With sixty units read in an even week, after a clean 36 tries, 7 misses in 24 are not a slip and 8 are. The learner naming a unit only narrows the list; it never makes a slip, and whether the unit was named a week ago, or for its pace, does not matter. A slip's row is always of misses. Pace is never called a slip: no spread is recorded for it to be tested against, so the list says nothing of a pair for getting slower. On simulated typists whose miss rates had not changed, light to very heavy practice, with and without good and bad days, a slip showed in 1 week in 100 or fewer; a common pair that went to 40% missed was listed in about 9 weeks in 10. A few typos this week, a like miss rate, a bad week, or a unit that only moved up the queue, is not a slip. Ranked by the change in the learner's gain, largest first; the first `SHOWN_MOVERS` (3) show and `#more-movers` shows the rest. Then the practice row (`li.mover.is-practice`): minutes the week before → this week, the streak (at the goal when one is set), "more", "less" or "same"; its "practice" button opens the practice calendar.
- **Charts.** `#week-charts` holds `#progress-period` (7 days, 30 days, All: the charts and the lists, never the lead) and two small charts, `#week-speed` and `#week-accuracy` (`renderWeekChart` in `src/progress-view.js`): the period's daily medians as one line, gridline values on the right, the last day's value at the line's end with its run count. Each is one button whose name describes the chart; it opens the fuller chart.

A detail view (`#progress-detail`) opens at its top, at once, and has `#progress-back` (back to the overview, focus to the link or chart that opened it), `#progress-detail-heading` (focused on opening), `#detail-filters` (the conditions control and period move here for runs, trends and keys; the period alone for the calendar) and one `[data-panel]`:

  - `trends`: `#progress-tabs` (accessible name "Chart"; Speed, Accuracy, Consistency, arrow keys move and show), `#progress-trend`, `#accuracy-trend` (each point a button that opens its day's latest run in `runs`), `#progress-spread`, `#trend-figures` (one mono line under the charts, such as "median 65 wpm · 93% accuracy · best run 80 wpm on Oct 17 · 4 runs": the period's median speed and accuracy, its fastest single run with its day, a tie going to the newest and a run without a date reading "date unavailable", and the runs counted, at the chosen conditions, the speeds as speed figures; hidden with no runs) and `#progress-trend-note`. The view stays open through its own period and condition filters, a period with no runs included. The charts, the line and the note are drawn together.   - `keys`: the key heat map (`#key-heatmap`, one tab stop, arrow keys; on a coarse pointer `#key-select`), `#key-detail`, "Pairs to watch" (`#pairs-table`), and Patterns across runs (see Completed run and recommendation).

## Accessibility and sizing

All controls are reachable by keyboard and use one focus ring (the accent outline). Mobile interactive targets are at least 44 px. The skip link targets `#typing-input`. Status updates use `#announcement`. IME composition, paste, touch-only input, and focus interruption are announced and displayed in `#input-help`; accent (dead) key compositions on `#typing-input` and `#race-input` are scored as the one or two characters they commit. A composition is an accent key's only if one opened it: its `Dead` keydown, before the mark shows or (Safari) just after, or a lone accent mark shown first, which is all Chromium on Linux gives (its keys arrive as `Process`). Any other composition, even one that commits a single Latin letter (Pinyin, Telex), is refused as IME text, as is a preview or commit no Latin keyboard key produces (another script's letter, digit or punctuation, CJK, kana, full-width, an emoji, more than a mark and a key; a Latin layout's own symbols, such as ’ — ⁴, still type) and a change to letters already typed such as the press-and-hold accent menu. Every key of a commit is scored before the passage can end; one carried past the last letter (`"h` on a closing `"`) is a mistake against that letter, is not kept, and shows as extra in the result's character breakdown, while one that is that letter (`""`) adds nothing; a Windows mark sent as an input of its own waits for the next key's input, so the pair is scored together there too. A held accent key's repeats are ignored like any key repeat (including the `Process` repeats Chromium on Linux sends), as is the letter that commits a mark it left pending, while another accent key pressed during the hold, or after the key is let go out of the field (focus elsewhere, a finished run), types as usual; a mark still pending when focus leaves is dropped; custom text takes accent keys like any other passage, and a commit made before a timed run's limit is scored even when its key arrives after the limit; interrupted attempts are never stored as comparable results. All motion scales to zero under `prefers-reduced-motion`.

`#import-trigger`, the last row of settings (and the palette command "import Monkeytype settings…"), opens `dialog#import-dialog`. `form#import-form` holds `#import-text` (the pasted export), `#import-choose` (opens the hidden `#import-file`, whose text fills the field), `#import-error` and `#confirm-import`, disabled while the field is empty. `src/monkeytype.js` parses and maps the export; matching settings are applied as picks (`saveChoice`), and a change of test conditions starts a new practice run. `#import-report` then replaces the form: `#import-summary` (how many settings, and whether they sync or last only for a guest's visit), `#import-mapped` and, when anything was left as it was, `#import-skipped-group` with `#import-skipped`. Each row names the Stilltype setting, the value or the reason, and the Monkeytype key it came from (`.import-from`). Custom lengths, the correction rule, strict space, quick end, minimums, repeat quotes, the keymap layout, typing sounds and sound volume are among the settings mapped (see `src/monkeytype.js` for the rules). Opening it mid-run marks the run interrupted, like the palette.
