## Bugs found on master

Fixed by open PRs:
- **#52:** the practice and race progress lines glided for 140 ms on every update during a run. They now step.
- **#54:** leaving a running drill for another view, or starting the daily mid-drill, drew a retest passage, marked it seen and threw it away, which burned a fresh quote.

Confirmed, fix in progress:
- **Profile sync loses data (confirmed).** Sync replaces the whole profile with no merge: a stale tab or device that saves anything, even a theme change, overwrites runs, traces, loops, bests and seen texts that another tab or device already synced. Bests can go down, and seen quotes are labelled fresh again. A fix PR, branch `claude/profile-sync-merge` (the number isn't known yet), is being built: merge before each push, a conditional write on `updated_at`, and merging on load and on the `storage` event. HANDOFF.md already says sync is last-writer-wins between devices; it doesn't mention two tabs in one browser.

Flagged, not fixed:
- **Input class on phones.** Tapping a button such as "Run again" focuses the field and opens the soft keyboard, so a run typed without tapping the field again counts as physical keyboard, and touch runs can land in keyboard bests. #47 and #49's `startedBy` is the start of a fix.
- **Caret clipped.** The caret sits at left −1.5px inside the passage wrap's `overflow: hidden`, so half of it is cut off at the start of each passage.
- **One-keyboard race.** It never sets `body[data-running]`, so the chrome doesn't fade during it.
- **Pointer nudge.** Moving the pointer clears `body[data-running]` mid-run to bring the chrome back, so still-run rules keyed only on it switch off while the run continues.
- **`.key` press transition.** On-screen keys animate each press for 80 ms (`--dur-micro`) beside the passage during a run, which the still-run rule doesn't allow. #52 now removes it unconditionally, as it does for the progress lines, because a pointer nudge clears `body[data-running]` mid-run. #49's `body[data-running="true"] .key` override becomes redundant once #52 lands; drop it when merging.
- **Passage sizes** are raw px (29/36/44, mobile 22/26/32), not tokens.
- **`.app-shell`** has no `min-width: 0` on its column. #45 works around it with `contain: inline-size`.

## Decisions waiting on you

1. **#24 themes.** There are eight opt-in proposal themes. Approve or reject each one. Afterimage stays the default and stays binding. A theme you approve only becomes binding once PRODUCT.md and DESIGN.md adopt it.
2. **Guest preferences.** New settings reset on reload for guests, because PRODUCT.md says guests keep nothing beyond the tab. This makes the restart key, pace caret and daily goal feel broken. Decide whether to change the guest contract.
3. **Paper redesigns.** These are on your laptop only. Commit them under `design/paper/` and a later session can build them as a proposal theme, the way #24 works.
4. **Cloudflare.** There's no Cloudflare config, check or deploy in the repo, and every PR deploys only to Vercel. The production Vercel URL is behind Vercel Deployment Protection. If a custom domain sits behind Cloudflare DNS, share the domain and it can be checked. The sandbox couldn't resolve it.
5. **#43: existing bests from repeated text.** #43's freshness gate isn't optional: PRODUCT.md allows improvement claims only on unseen text, and master lets an exhausted-pool run (repeated text) set a best, a trend point and pattern evidence. The decision is how to treat bests already stored from repeated text. #43 recomputes bests from fresh runs only, so such a best falls back to the best fresh run or is dropped on load. The alternative is to keep old bests and label them "repeated text". Choose before #43 merges.
6. **#48 composing wpm.** Free-typing wpm counts the characters left in the final text, not every key pressed; deletions show only in the backspace rate. The brief said "characters typed per active minute", which would count every key. Approve the final-text reading or ask for keys pressed.
7. **#44 standard test.** Standard is a mode, not a run kind, so its runs count toward bests, trends and retests under their own `recipe` key. Its "one quote segment" is a generated sentence in quotation marks, not a corpus quote, so the text stays fresh. The alternative, natural corpus prose, needs a larger segment-level pool with its own freshness tracking.
8. **Ghosts under reduced motion.** #47 hides the raced ghost; #55 steps the recorded ghost key to key with no transition. Pick one rule before both merge. AGENTS.md says motion scales to zero, which favours hiding it or a static marker; stepping keeps the opponent visible.
9. **#49 lessons on touch.** A lesson pass counts only on a physical keyboard. A touch run is saved as a labelled try but never unlocks the next lesson, so a phone is stuck at lesson 1. Options: keep this, hide the learn path on touch-only devices, or add a separate touch track.
10. **#47 trailing ghost.** An open review thread notes that a trailing ghost that has scrolled out of view has no "behind" indicator. The ghost hides only once it is 3 or more rows above the visible window. An indicator would be a design addition, so it's left open for you.
11. **#55 unseen results.** A result counts as unseen for 7 days, because there's no "seen" column. A device that checks in less often than weekly can miss one. The alternative is a server-side "seen" column.
12. **#46 layouts.** Pair evidence and recommendations are split per layout (legacy runs read as QWERTY), and changing the layout resets to a practice run, discarding a running or prepared attempt. The alternatives are evidence shared across layouts, which mixes a slow QWERTY pair into Dvorak advice, and a layout change that keeps the current session.
13. **Trade-offs the fixers chose.** Push back on any of these you disagree with:
   - **#19:** the palette's "restart test" now repeats the current kind of test (daily, drill) instead of always starting practice.
   - **#27:** practice time beyond the 1,000-run limit is kept in a per-day archive covering 730 days.
   - **#27:** under a minute shows as "<1 min".
   - **#28:** custom text needs at least 2 words and 10 characters. A run that ends inside one second shows "—" instead of a WPM, so a typist above about 110 wpm sees "—" on a 10-character text. A 20-character minimum would avoid that but would refuse "hello world".
   - **#28:** custom results hide the drill, retest and recommendation; only Run again stays.
   - **#34:** the break suggestion fires by chance about 11% of the time at run 8 when nothing has changed. It shows at most once per sitting and states its counts.

## Conventions this sprint set

- **Branches and PR bodies.** One feature per branch, named `claude/<slug>`. PR bodies use What / Changes / Screenshots / Tests.
- **Screenshots** are written to `docs/screenshots/<slug>/` only with `SCREENSHOTS=1`. Without it they go to Playwright's output folder, so normal test runs no longer rewrite committed images. Screenshot specs type at about 70 ms per key so the images show believable speeds.
- **Browser tests:**
  - Run them with `CHROMIUM=/opt/pw-browsers/chromium E2E_PORT=<unique port> npx playwright test <spec> --workers=1`.
  - Give each parallel run its own port.
  - **Never `pkill` the node server.** One agent did, and it killed every other agent's test server.
- **The Codex review bot** posts P1/P2 findings on every push. Each round was checked against AGENTS.md before fixing. Findings that didn't apply were answered on the thread and resolved: for example, the request to "keep unapproved themes out" on #24, where you had asked for opt-in proposals.
- **Local only, not committed:** `.claude/worktrees/` and the `node_modules` symlink are listed in `.git/info/exclude`. #29 changes `.gitignore` from `node_modules/` to `node_modules` so a symlink is ignored too.
